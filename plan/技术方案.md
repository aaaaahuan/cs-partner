## 一、系统架构总览

### 1.1 整体架构

### 1.2 线程模型

```
主线程 (Qt Event Loop)
├── UI 渲染 (paintEvent)
├── Signal/Slot 接收
└── QTimer 驱动

逻辑线程 (daemon=True)
├── 100ms 轮询循环
├── 调用 mss 截图
├── 调用识别引擎(核心模块)
└── 发射 Signal → 主线程更新 UI

热键线程 (keyboard 库内部线程)
├── F1 → set_mode(1)
├── F2 → set_mode(2)
└── F5 → record_current_position()
```

**线程安全保障**：所有跨线程通信均通过 `pyqtSignal` 进行，Qt 的 Signal/Slot 机制在不同线程间自动使用队列连接（QueuedConnection），确保 UI 操作只在主线程执行，避免竞态条件。

`mss` 库不是线程安全的，因此每次调用都在函数内部使用 `with mss.mss() as sct` 创建新实例，而非共享单一实例。

### 1.3 数据流

  image_path  = 全屏参考截图 (1920×1080)，玩家对准目标时的画面
  aim_point_x = 960   ← 准星始终在屏幕中心
  aim_point_y = 540

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 二、各模块详细设计

### 2.1 屏幕捕获层 (`core/minimap.py` → `grab_minimap()`)

**职责**：截取屏幕左上角小地图区域，供识别引擎使用。

**捕获区域定义**（以 1920×1080 为基准）：

```python
minimap_region = {
    "top": 20,    # 距屏幕顶部 20px（避开状态栏）
    "left": 20,   # 距屏幕左侧 20px
    "width": 500, # 小地图宽度区域（包含周边，容错用）
    "height": 350 # 小地图高度区域
}
```

**多显示器处理**：使用 `sct.monitors[monitor_index]` 的 `top/left` 偏移量，确保在多显示器环境下捕获正确的屏幕。

**输出格式**：`numpy.ndarray`，BGR 颜色空间，shape `(350, 500, 3)`。

**性能**：单次捕获耗时约 1-2ms（BitBlt API，无 GPU 参与）。

---

### 2.2 小地图识别引擎（ORB 特征匹配）

**前提**：强制要求游戏设置 `cl_radar_always_centered 1`（玩家图标固定在雷达中心，地图随视角旋转）。

> 选择此模式的原因：玩家图标始终居中，排除了通过颜色检测箭头坐标的必要性；且 CS2 玩家普遍开启此选项以便于观察周围地形。系统录制时捕获的是"玩家站在这里时的雷达截图"，回放时与实时截图对比，判断是否在同一位置。

**算法流程**：

```
录制阶段（一次性）：
  玩家站在投掷位置
    ↓ grab_minimap() 截取雷达区域
  保存小地图截图作为"位置指纹" → minimaps/xxx.png
    ↓ ORB.detectAndCompute()
  提取并缓存特征点 (kp_stored, des_stored)

回放阶段（每 100ms）：
  grab_minimap() → 实时雷达截图
    ↓ ORB.detectAndCompute()
  提取实时特征点 (kp_live, des_live)
    ↓ BFMatcher(NORM_HAMMING, crossCheck=True).match()
  所有匹配对 → sorted by distance → 取 top-20
    ↓ avg_distance
  相似度分数（越低越匹配）
    ↓ < SIMILARITY_THRESHOLD (35.0)
  触发：玩家在 "xxx 点位" 附近
```

**ORB 参数设计**：

| 参数 | 值 | 理由 |
|------|-----|------|
| `nfeatures` | 500 | 雷达图像信息密度适中，500 个特征点足够区分不同位置 |
| `NORM_HAMMING` | — | ORB 使用二进制描述符，Hamming 距离是唯一正确度量 |
| `crossCheck=True` | — | 仅保留双向最优匹配，降低误匹配率约 30% |

**SIMILARITY_THRESHOLD 说明**：

| 分数范围 | 含义 | 行为 |
|---------|------|------|
| < 25 | 极高相似（几乎同一位置和角度） | 高置信触发 |
| 25–35 | 良好匹配（同一位置，视角有小偏差） | 正常触发 |
| 35–50 | 弱匹配（相邻位置） | 不触发 |
| > 50 | 不匹配 | 跳过 |

**性能**：单次匹配约 3-5ms（500px×350px 的小地图，nfeatures=500），在 100ms 轮询内完全不是瓶颈。

### 2.3 点位匹配器 (`main.py` → `GameLogic.loop()`)

**匹配逻辑**（只用 ORB，无双分支）：

```python
# 遍历所有有 minimap_path 的点位
best_score = float('inf')
for g in grenades:
    score = tracker.compare_current_view(g['minimap_path'])
    if score < SIMILARITY_THRESHOLD(35.0):
        nearby.append(g)
        if score < best_score:
            best_score = score
            active = g
```

**SIMILARITY_THRESHOLD = 35.0**：

| 分数 | 判断 |
|------|------|
| < 35 | 触发（nearby + active） |
| ≥ 35 | 跳过 |

### 2.4 覆盖层渲染 (`core/overlay.py`)

**窗口属性**：

```python
setWindowFlags(
    Qt.FramelessWindowHint      # 无边框
  | Qt.WindowStaysOnTopHint     # 永远置顶
  | Qt.Tool                     # 不占任务栏
)
setAttribute(Qt.WA_TranslucentBackground)        # 透明背景
setAttribute(Qt.WA_TransparentForMouseEvents)    # 点击穿透
setGeometry(0, 0, screen_width, screen_height)  # 铺满全屏
```

**点击穿透原理**：`WA_TransparentForMouseEvents` 使 Qt 将所有鼠标事件转发给其下方的窗口（即 CS2）。底层通过 Windows API `SetWindowLong(hwnd, GWL_EXSTYLE, WS_EX_TRANSPARENT)` 实现。

#### Mini 小窗模式（F1）

```
屏幕右上角固定区域 400×300px
┌─────────────────────────────┐
│ 参考瞄准截图 (180px 高)      │  ← QPixmap 缩放显示
│                             │
├─────────────────────────────┤
│ 点位名称 (黄色加粗)          │  ← QPainter.drawText
│ Type: Smoke                 │
│ Action: 左键投掷             │
└─────────────────────────────┘
```

背景：半透明黑色 `QColor(0, 0, 0, 200)`，黄色边框 `QPen(QColor("yellow"), 2)`

#### Ghost 全屏蒙层模式（F2）

参考截图以 `30% 透明度（setOpacity(0.3)）` 铺满全屏，玩家游戏视野与参考图同时可见，实现像素级准星对齐。

```python
painter.setOpacity(0.3)
painter.drawPixmap(px, py, scaled_pixmap)  # 等比缩放到屏幕尺寸
painter.setOpacity(1.0)
```

**透明度选择依据**：0.3（30%）是在"可见参考"与"不遮挡视野"之间的最优权衡，经实测不影响正常游戏操作。

#### Toast 通知

显示位置：屏幕上方 1/4 处（`cy = screen_height // 4`），绿色圆角背景，白色文字，持续时间由调用方指定（ms），通过时间戳判断是否过期。

### 2.6 数据层 (`core/data_loader.py`)

**文件结构**：

```
cs_partner_data/
├── grenades.json          # 所有地图点位数据
├── images/                # 瞄准参考截图
│   └── custom_*.png
└── minimaps/              # 小地图指纹（ORB 匹配用）
    └── minimap_*.png
```

**grenades.json 完整格式**（含瞄准点坐标）：

```json
{
  "maps": {
    "inferno": {
      "name": "Inferno",
      "grenades": [
        {
          "name": "Banana CT Smoke",
          "type": "Smoke (烟雾弹)",
          "desc": "封锁 CT 视野，从香蕉道推进",
          "aim_desc": "左键普通投掷",
          "image_path": "images/inferno_banana_ct.png",
          "minimap_path": "minimaps/inferno_banana_ct.png",
          "aim_point_x": 960,
          "aim_point_y": 540
        }

```

> `aim_point_x / aim_point_y`：录制时玩家准星在参考截图中的像素坐标。CS2 准星固定在屏幕中心，1920×1080 下默认为 (960, 540)。瞄准点追踪引擎将把这个坐标投影到当前帧的实际像素位置。

**PyInstaller 路径适配**：`get_resource_path()` 通过检测 `sys.frozen` 标志，在开发环境使用 `os.path.abspath(".")` 作为基准，在打包 EXE 环境使用 `os.path.dirname(sys.executable)`，确保路径在两种环境下都正确。

### 2.7 瞄准点追踪引擎 (`core/aim_tracker.py`)

**核心问题**：玩家站在投掷位后，需要知道准星应该指向屏幕哪个位置。随着玩家原地转身，目标物体在游戏画面中的位置会发生变化，不能简单地固定在屏幕中心显示叠层。

**解决方案**：用 ORB 特征点 + 单应矩阵（Homography）将录制时的准星坐标投影到当前帧。

**算法流程**：

```
离线（首次访问该点位时，缓存一次）：
  载入参考截图 (image_path) → 缩小到 50% 加速
    ↓ ORB.detectAndCompute()
  (kp_ref, des_ref) 缓存到内存

在线（每 100ms）：
  grab_game_view() → 当前全屏画面 → 缩小到 50%
    ↓ ORB.detectAndCompute()
  (kp_cur, des_cur)
    ↓ FLANN knnMatch(k=2) + Lowe 比率过滤(0.75)
  good_matches（质量好的匹配对）
    ↓ >= MIN_GOOD_MATCHES (15)
  cv2.findHomography(RANSAC, reprojThresh=5.0) → H
    ↓ perspectiveTransform(aim_point_ref, H)
  → 投影坐标 * 2（恢复全分辨率） → (screen_x, screen_y)
    ↓
  返回 (screen_x, screen_y, confidence)
  或 None（目标不在视野内 / 匹配不足）
```

**关键设计决策**：

| 决策 | 方案 | 理由 |
|------|------|------|
| 匹配算法 | FLANN（近似 KNN）| 比 BFMatcher 快 3-5x，适合 1500 个特征点 |
| 过滤方法 | Lowe 比率测试（0.75）| 去除歧义匹配，precision 大幅提升 |
| 几何估计 | findHomography + RANSAC | 对误匹配点鲁棒，4 点即可求解 |
| 图像缩放 | 50%（960×540）| 提取特征速度提升 4x，精度损失可接受 |
| 最小匹配数 | 15 | 低于此值则单应矩阵不稳定，返回 None |

**渲染策略（覆盖层根据 aim_point 结果决定显示方式）**：

```
aim_point = (screen_x, screen_y, confidence)   ← 目标在当前视野内
  → 在 (screen_x, screen_y) 绘制绿色准星圆圈
  → 绿色文字显示投掷方式（"左键普通投掷"）

aim_point = None   ← 目标不在当前视角
  → 显示黄色提示："转向目标位置"
  → Mini 模式：显示参考图卡片（告诉玩家应该看哪里）
  → Ghost 模式：30% 透明参考图铺全屏（辅助对齐视角）
```

**性能估算**（1920×1080 → 缩小到 960×540）：

| 步骤 | 耗时 |
|------|------|
| mss 截图 | 2ms |
| 缩放 | 1ms |
| ORB 特征提取（1500 points） | 8-12ms |
| FLANN 匹配 | 3-5ms |
| Homography | 1ms |
| **合计** | **15-20ms** |

100ms 轮询周期内完全可接受。且只有 `active_grenade` 存在时才触发，大部分时间不执行。

## 三、核心算法选型对比

### 3.1 屏幕捕获方案

| 方案 | FPS 上限 | CPU 占用 | 延迟 | 依赖 | 适用性 |
|------|---------|---------|------|------|--------|
| **mss（当前选择）** | 60-120 | 1-3% | 1-2ms | 无额外依赖 | ✅ 最优 |
| PIL.ImageGrab | 30-60 | 3-5% | 3ms | Pillow | 备用兜底 |
| dxcam | 240+ | 1-2% | <1ms | DirectX | 高帧率需求时升级 |
| d3dshot | 120-240 | 2-4% | 1ms | DirectX | 配置复杂 |

**选择理由**：本工具以 100ms（10fps）为轮询周期，mss 的 60fps 能力远超需求。mss 无额外系统依赖，打包体积最小，且在 AMD/NVIDIA 双显卡下兼容性最佳。

### 3.2 图像特征检测算法

| 算法 | 旋转鲁棒 | 速度 | 精度 | 许可证 | 本项目适用 |
|------|---------|------|------|--------|----------|
| **ORB（当前选择）** | 中等 | ⚡ 3-5ms | 良好 | 开源 | ✅ 速度最优 |
| SIFT | 优秀 | 🐢 30-50ms | 优秀 | 专利到期 | 精度优先场景 |
| AKAZE | 较好 | ⚡ 5-10ms | 较好 | 开源 | ORB 的升级替代 |
| 模板匹配 | ❌ | ⚡ <1ms | 仅无旋转 | 开源 | 固定雷达补充 |

**选择理由**：旋转雷达场景的核心诉求是"判断是否在同一位置"，不需要极高精度，ORB 在速度和效果之间取得最佳平衡。SIFT 精度更高但 30-50ms 的单次计算在遍历多个点位时会造成明显延迟。

### 3.3 GUI/覆盖层框架

**选择理由**：点击穿透是覆盖层的核心需求，PyQt5 的 `WA_TransparentForMouseEvents` 提供最简洁的实现。pygame 虽然在游戏场景更常见，但实现点击穿透需要调用原生 Windows API，增加了复杂度。

## 四、关键技术挑战与解决方案

### 4.1 旋转雷达兼容

**问题**：`cl_radar_always_centered 1` 时，地图随玩家视角旋转，无法用固定坐标匹配点位。

**解决方案**：在录制时同步捕获小地图指纹图像，运行时用 ORB 特征匹配判断当前视图与哪个录制点位最相似（score < 35）。

**局限性**：ORB 对大角度旋转（>45°）的鲁棒性有限。后续可引入旋转不变检测（如 AKAZE）或用 Hough 直线检测先估算旋转角度再做对齐。

### 4.2 分辨率自适应

**问题**：小地图位置和尺寸随屏幕分辨率变化，当前代码针对 1920×1080 硬编码。

**解决方案**：启动时检测屏幕分辨率，按比例缩放捕获区域：

```python
scale_x = screen_width / 1920
scale_y = screen_height / 1080
minimap_region = {
    "top":    int(20 * scale_y),
    "left":   int(20 * scale_x),
    "width":  int(500 * scale_x),
    "height": int(350 * scale_y)
}
```

### 4.3 mss 线程安全

**问题**：`mss.mss()` 实例不能跨线程共享（在录制热键线程中调用会崩溃）。

**解决方案**：每次调用截图函数时在函数内部创建新的 `mss` 实例（使用 `with mss.mss() as sct`），避免实例跨线程传递。代价是每次创建实例有约 0.5ms 的额外开销，在 100ms 轮询周期下可以接受。

### 4.4 VAC 安全性

**工作原理**：本工具 **完全不读取 CS2 进程内存**，仅通过 Windows GDI/BitBlt API 截取屏幕画面（公开可见信息）。VAC（Valve Anti-Cheat）检测的核心是：内存读写、DLL 注入、驱动级钩子。本工具与这些行为无关。

**安全边界**：
- ✅ 不调用 `ReadProcessMemory` / `WriteProcessMemory`
- ✅ 不注入 DLL 到 cs2.exe
- ✅ 不修改游戏文件
- ✅ 不使用内核级驱动
- ⚠️ 需要窗口化全屏模式（游戏独占全屏模式下无法覆盖显示）

### 4.5 Qt 版本兼容性

**问题**：`QFontMetrics.width()` 在 PyQt5 5.11+ 已被废弃，PyQt5 5.15 中报 `AttributeError`。

**解决方案**：改用 `fm.horizontalAdvance(text)`（PyQt5 5.11+ / PyQt6 同样适用）。

## 七、后续演进路线

### P1 短期优化（核心体验提升）

**① 分辨率动态适配**
启动时根据 `QScreen.size()` 计算 minimap_region 缩放比例，支持 2K/4K 屏幕。

**② 旋转角度估算**
在 ORB 匹配基础上，用 Hough 直线检测估算当前雷达旋转角度，与保存时的角度做差后旋转对齐，提升旋转雷达下的匹配精度至 95%+。

```python
def estimate_rotation_angle(img):
    edges = cv2.Canny(img, 50, 150)
    lines = cv2.HoughLines(edges, 1, np.pi/180, 30)
    if lines:
        angles = [np.degrees(l[0][1]) for l in lines]
        return np.median(angles)
    return 0
```

**③ 多点位卡片切换**
当同一位置有多个点位时，在 UI 中以 ←/→ 箭头切换显示，而不是只显示最近的一个。

### P2 中期功能扩展

**④ 地图自动检测**
截取计分板或地图加载画面，使用 OCR（pytesseract）或模板匹配自动识别当前地图，无需手动修改 `current_map`。

**⑤ 玩家箭头方向识别**
通过 Hough 变换检测箭头主轴方向，输出玩家朝向角度（0-360°），用于：
- 旋转雷达下更精确的坐标换算
- 可选的"已转向目标位置"提示

**⑥ 点位导入/导出**
支持将自己的 `grenades.json` 打包为 `.cs2p` 文件分享给队友，队友拖入软件目录即可导入。

### P3 长期愿景

社区贡献点位，按地图/版本分类，一键下载订阅，类似 CS:GO 的 Workshop 机制。
